## Canonical pipeline and activation boundary

There is still one orchestration entry point: run_research_assistant.
For new queries it performs strict parse/decode, deterministic capability
policy, canonical resolution, fixture catalog/record-existence validation,
final analysis planning, guarded explicit executor dispatch, deterministic
evidence, grounded interpretation and the existing entailment stages.
Legacy requests retain the existing routing and execution behavior.

Registry version is 1.3.0-phase5.1. sex_age, sex_rurality and age_rurality remain
PLANNED, validation pending, with empty public function/surface bindings.
Understanding or normalizing a query does not make it executable.

Without a fixture context, a recognized public request returns status planned,
a typed SemanticCapabilityDecision with executable=False, and a normalized
interpreted-query draft. Its availability status is not_checked_activation_pending.
It does not invent canonical cause/demographic IDs, query a warehouse or emit
results. Full public catalog resolution/activation is deliberately not enabled
in this checkpoint. Real-data checks are still required before that workflow
can be connected to public execution.

Exact integration is exercised only with FixtureIntegrationContext:

- a typed explicit Python argument, never parser JSON or an environment toggle;
- an existing file under the system temporary directory, at most 16 MiB;
- a mandatory synthetic_structural_fixture_only marker in a dedicated fixture table;
- a path distinct from the configured analytical warehouse;
- read-only access, with allow_execution=False unless explicitly enabled by the test;
- a content-bound availability receipt checked again at execution.

Catalog-only fixture mode can resolve and plan while still returning planned.
Missing catalogs/records return structured clarification or unavailability.
An unmarked file, untyped context, missing execution permission, changed file,
missing receipt, tampered preview/query/assumptions or unapproved function is
blocked. None of these fixture controls constitutes real-data activation.

## Parser/schema and normalization

The existing strict parser schema gains nullable multidimensional with:

- fixed_sex, fixed_age, fixed_race_ethnicity;
- comparison_dimension and independent structured group_a/group_b populations;
- rurality_grouping, rurality_filter and state_name;
- intended compare_groups, summarize_by_rurality or unsupported operation.

Existing cause/county/scope and point/range-year fields remain in the typed
request. Group populations contain independent sex, age, race/ethnicity and
rurality labels. No demographic ID, SQL/function name, file path or activation
flag is accepted. Additional keys and non-string population labels fail strict
decoding. Competing legacy demographic fields require clarification rather
than silently discarding one encoding. Legacy single-dimension requests keep
multidimensional=null.

Normalization never treats women ages 40-44 as one group label. It canonicalizes
independent labels, validates shared versus changing dimensions, rejects two
changing demographic dimensions and preserves comparison orientation. Qualitative
age labels need clarification. Numeric time ranges remain intact. RUCC 2023
is treated as a classification timestamp, separately from a selected/defaulted
IHME observation year; unsupported observation years are not replaced.

## Explicit capability-specific defaults

MULTIDIMENSIONAL_POLICY_DEFAULTS is an immutable registry mapping:

| Capability | Deterministic population defaults when unspecified |
| --- | --- |
| sex_age | Race=Total |
| sex_rurality | Race=Total; age=20+, age standardized |
| age_rurality | Race=Total; sex=Both sexes |

Policy also records any selected default source, county universe, RUCC grouping
and code-envelope default year (2019). This is a policy year, not a claim that
all source combinations are observed. Exact fixture cause/year/stratum records
must still be found before a final executable fixture plan is produced.

Every inserted default carries multidimensional-policy-1 and its capability
key in the immutable query assumptions, plan and complete interpreted-query
metadata. Provided constraints are not overwritten. An unstated total,
standardized age basis or year chosen by the model is not accepted as a policy
default. Explicit Total race is retained without being labeled a policy choice.
Both sexes is never substituted for an explicit Female/Male filter.

The required standardized basis for sex-rurality is the tested intended
Phase 3/4 envelope, expressed as explicit policy. Its real-data availability
and provenance remain unvalidated; it does not authorize public execution.

## Resolver, availability, planner and executor

Cause/county resolution reuses the canonical conservative matching and
ambiguity behavior, with optional catalogs supplied only by the guarded
fixture integration. Existing callers use the same original catalog defaults.
The new path checks that the requested cause/county is consistent with the
original question. State scope derives from the existing canonical county
catalog and must be unambiguous; scope filters are never removed to fit data.

Sex, age and race values remain independent and resolve through the Phase 4
reader's existing small dimension catalogs, including ambiguity detection.
No compound population label is sent to the old one-dimension group resolver.
A catalog-missing combination or absent exact cause/year/stratum yields
unavailability, not a fallback disease, age, sex, year or national scope.
Availability checks read catalog values and exact record existence, not rate
estimates; they do not certify complete county coverage, uniqueness or usable
estimates across a real source. Phase 4 execution still supplies those detailed
coverage/missingness diagnostics and rejects duplicate analytical keys.

A final new plan contains the full immutable ResolvedQuery, capability/version,
required sources, exact groups/orientation, geography, time and assumptions.
Its preview includes a complete JSON-safe representation and query digest.
The availability receipt binds the fixture contents and query. The executor
repeats assess_query_contract, preview/query/plan identity and receipt checks
immediately before its explicit compare_strata or summarize_by_rurality call.
The result query must also match the executed plan before evidence conversion.

Model-provided function names are impossible in the strict semantic schema.
The two guarded bindings are separate from the unchanged legacy public
APPROVED_FUNCTIONS map. Existing dataframe, measurement-year/carry-forward and
analysis-year transforms are checked with permanent offline tests.

## Conservative request policy

Unsafe new shapes are rejected rather than downgraded: sex-age-rurality,
unvalidated race intersections, two changing demographic dimensions,
additional unsupported dimensions, PLACES subgroup prevalence/new unapproved
cross-source mappings, forecasts, causal/inferential requests, unsupported
outcome metrics/years and mixed age-standardized/age-specific comparisons.
Ambiguous labels and competing semantic encodings remain clarification cases.
County names such as White County are not interpreted as race constraints.

No conversational fallback, alternatives, multi-turn state or Streamlit work
is included. The existing structured clarify/reject mechanisms are reused.

## Evidence and grounded interpretation

The existing EvidenceBundle/EvidenceItem pipeline retains the immutable Phase 4
result, full coverage, explicit population basis, comparison orientation,
RUCC 2023 fixed-lens note, separate marginal uncertainty bounds and source
semantics. Context/metadata are JSON-safe for the interpretation provider.
Rate claims explicitly carry unknown units; IHME attribution stays unknown.
County summaries are described as equally weighted county means/medians over
disjoint groups, not population-weighted national estimates.

Dedicated deterministic findings, methods and limitations prevent new evidence
from inheriting legacy generic burden/attribution language. Additional checks
reject prose that upgrades unknown attribution/unit scale or unsupported
weighting/difference intervals. These supplement, rather than replace, existing
structural grounding, numeric/direction/causal checks and model entailment.
A failed narrative is withheld with ai_error under the existing canonical
behavior; deterministic evidence remains available. No unsupported narrative
is treated as a validated interpretation.
