## Canonical integration

`run_research_turn` is a control wrapper over `run_research_assistant`, not another
analytical assistant. Every accepted research request/merge enters the same
semantic-parser interface, typed request, capability/policy checks, canonical
resolver, availability validation, plan, guarded executor, deterministic APIs,
evidence, grounded interpretation and entailment. Deterministic short answers
such as an observation year or pending source choice fill typed fields through
that parser interface; no model is needed to interpret “Both” or “2019”.

Capability questions return deterministic control-plane descriptions without
claiming analytical results. Non-answer outcomes receive optional structured
`failure_reason` and `conversation_response` metadata. Existing one-shot APIs and
legacy error exceptions remain compatible. `conversation_mode=True` is used by
the new turn wrapper to ask explicit source/year questions before inheriting
legacy defaults, and to return sanitized infrastructure outcomes. The normal
one-shot analytical behavior remains intact.

A missing-year conversational request is not executed with the legacy latest-year
default. Source choices are explicit. Neither defaults nor suggestions overwrite
researcher constraints. The Phase 5 fixture context remains explicit, typed,
marked, temporary and independently guarded; it is not carried in state.

## Structured reasons

| Reason | Meaning |
| --- | --- |
| `DATA_UNAVAILABLE` | Checked requested combination lacks required records |
| `YEAR_UNAVAILABLE` | Requested observation year is outside applicable supported policy bounds |
| `HEALTH_CONCEPT_UNAVAILABLE` | Requested concept could not match the checked source catalog |
| `DEMOGRAPHIC_COMBINATION_UNSUPPORTED` | Population intersection/comparison exceeds validated envelope |
| `GEOGRAPHIC_COMBINATION_UNSUPPORTED` | Geography/grouping exceeds validated envelope |
| `OPERATION_UNSUPPORTED` | Unsupported operation, including forecast or causal inference |
| `AMBIGUOUS_COUNTY` | County requires disambiguation, normally a state |
| `AMBIGUOUS_HEALTH_CONCEPT` | Health concept not uniquely resolved |
| `AMBIGUOUS_DEMOGRAPHIC_VALUE` | Population value cannot be uniquely normalized |
| `CAPABILITY_PLANNED_NOT_ACTIVATED` | Understood capability awaits real warehouse activation |
| `INFRASTRUCTURE_UNAVAILABLE` | Required database, API or service failed; scientific availability is unknown |
| `SOURCE_REQUIRED` / `YEAR_REQUIRED` | Explicit conversational source/year choice needed |
| `INTENT_AMBIGUOUS` | Unresolved intent or unsafe referent |
| `CONTRADICTORY_FOLLOW_UP` | Proposed replacement of an existing constraint requires confirmation |
| `STATE_INVALIDATED` | Version/catalog change, expiry or bounded-state limit requires restatement |

Structured codes take precedence over the compatibility adapters for existing
text-based policy/resolution reasons. Unknown legacy reasons remain intent
ambiguity. An empty/malformed lookup is not proof of scientific data absence.
Exceptions never become `DATA_UNAVAILABLE`. Service details and exception text
are not exposed in conversational responses.

## Alternatives and self-description

Alternatives are proposals with registry key, operation label, exact registry
state, evidence sources, registry restrictions, deterministic closeness score,
and explicit `availability=not_checked`. They contain no executable arguments,
SQL or callable. Only assistant-surface executable paths and explicitly labelled
planned capabilities are considered. No unsupported capability is proposed.

Ranking favors the requested source, county scope, demographic comparison and
rurality dimension, with a small planned-state penalty. Stable keys break ties;
at most three options are returned. A resolved cause outside the exact approved
PLACES–IHME pair IDs excludes paired-source proposals. Unresolved paired-source
options explicitly require an approved pair. PLACES-only demographic requests
are never represented as executable subgroup prevalence.

Catalog-nearby concept labels use lexical similarity only as researcher-choice
proposals, never as cause mappings. The canonical resolver and exact approved
pair policy must still validate a new request. No suggestion executes or removes
a constraint automatically.

Deterministic summaries answer capabilities, diseases, years, sex comparisons,
rurality comparisons and breast-cancer coverage questions. They separate
registered executable code paths from PLANNED capabilities and unsupported
operations. Static year bounds are described as code/policy envelopes, not
observed county/stratum coverage. PLACES semantic years start in 2018 despite the
direct API envelope starting in 2017. RUCC is explicitly a fixed 2023 geographic
classification. Breast cancer is never substituted with PLACES CANCER.

Without checked catalogs, summaries explicitly require a live catalog check to
confirm condition coverage. `load_capability_catalog()` is an explicit read-only
refresh in one database transaction, using canonical relation identifiers. It
fingerprints cause, sex, age, race, county, RUCC and PLACES catalogs plus observed
source years. Failures propagate rather than producing an empty checked catalog.
A catalog listing/year does not establish usable outcome coverage.

## Bounded state and follow-ups

`ResearchState` is frozen and caller-owned in memory. It stores a bounded current
structured intent, registry version, catalog fingerprint, creation time, turn
count, pending field, and at most one proposed replacement intent. It stores no
prior evidence, results, transcript, execution permission or fixture context.

Bounds are eight turns, thirty minutes, a 4,000-character question and at most
8,192 UTF-8 bytes per serialized intent/proposal. Expiry, turn exhaustion,
registry change or a changed relevant catalog fingerprint invalidates the state
and requires a complete restatement. Callers must supply a current catalog
snapshot when catalog-backed context is available; an unknown snapshot does not
claim that catalog changes have been observed.

An explicit answer fills a pending slot. A state answer appends a state label to
the ambiguous county, then canonical county resolution must validate it; no FIPS
is guessed. Partial typed follow-ups merge only supplied fields and preserve all
others, including fixed population filters, disease and county scope. Replacing
an existing field surfaces a contradiction and holds a proposal; “confirm change”
reruns full canonical validation on the proposed intent. Ambiguous pronouns and
unresolved references ask for clarification.

The raw lexical constraints of the current intent are retained across merges,
including unsupported constraints the parser may have omitted. Rebuilding only
successfully parsed fields would incorrectly weaken rejected questions. This is
covered by a permanent regression test. Parser outages preserve the prior intent.
A modified query never inherits prior evidence or interpretation.

Capability descriptions can be requested during clarification without destroying
the pending research state. State is not written to telemetry or a new backend.
Telemetry retains legacy categories and adds only `infrastructure_error` and
`capability_summary` enum values; raw questions/state remain excluded.

## Representative responses

The following are excerpts of deterministic responses; full responses include
registry-backed, state-labelled options and an invitation to choose/rephrase.

- Planned sex × age: “I understand you want to analyze the requested health
  condition, specifically among women, comparing age groups. EpiCounty can
  represent this multidimensional analysis, but it is implemented and not yet
  activated against the production analytical warehouse.”
- Unsupported intersection: “This population combination is outside the validated
  capability envelope. Multiple changing demographic dimensions, race
  intersections, and sex × age × rurality cannot be executed.”
- Unsupported IHME year: “The requested observation year is outside the applicable
  validated policy period, 2000–2019. I have not substituted another year.”
- Infrastructure: “A required API, database, or execution service could not
  complete the request. I cannot determine scientific data availability from
  this infrastructure failure.”
- Source clarification: “Do you want CDC PLACES prevalence, IHME burden, or both?
  The sources measure different outcomes; a combined analysis requires an
  approved concept pair and supported operation.”
- Contradiction: “This changes existing constraints (year). Say ‘confirm change’
  or specify a correction.”

No fallback computes or invents epidemiological estimates, upgrades unknown IHME
attribution/unit scale, implies PLACES subgroup estimates, describes RUCC as
historical rural-status change, or describes planned capability as live.
