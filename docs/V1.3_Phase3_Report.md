## Contract structure

All contracts use frozen dataclasses and immutable nested values. They require
typed enums and canonical structured values rather than accepting arbitrary
parser dictionaries. New contracts do not replace or modify legacy models.

| Contract | Fields and invariants |
| --- | --- |
| DemographicStratum | Independent sex, age and race/ethnicity PopulationValue fields. Unspecified, total, subgroup and unavailable are separate states; unavailable has an explicit reason and can retain the requested value. Total age is not an age-standardized category. |
| ComparisonSpec | Exactly one typed dimension and two distinct, explicit subgroup values. Group dimensions must match. Duplicate/overlapping age groups, standardized-versus-age-specific comparisons and incompatible rurality groups are rejected. |
| GeographySpec | Geography mode, optional canonical county/state FIPS scopes, rurality filter, explicit RUCC 2023 classification year when required, existing eligible-county universe and report-exclusions missingness policy. Classification time is not health-observation time. |
| TimeSpec | SourceTime entries retain exact sorted source-specific year selections or expanded explicit ranges, release policy/year and single-source, same-years or contextual alignment. PLACES measurement and release years remain distinct. Cross-source measurement evidence uses canonical non-carry-forward selection. No silent range intersection or year replacement. |
| ResolvedQuery | Canonical source concepts/IDs, stratum, comparison, operation, geography, time, assumptions, registry/contract versions and optional availability fingerprint. Fixed/comparison conflicts, stale registry versions, mismatched source/time metadata and unapproved concept pairs are rejected. Required sources derive from health concepts plus requested rurality. |
| CapabilityDecision | Retains the exact query object, typed status/reason, explanation, missing constraints and immutable explicit alternatives. Statuses cover planned, clarify, unavailable, unsupported and legacy-unverified. No status authorizes execution in Phase 3. |

Supporting SourceConcept retains the Phase 2 Attribution contract. IHME
attribution defaults to unknown; verified attribution must retain matching
dataset/version provenance. No real attribution provenance was verified here.
RUCC cannot be used as a health-outcome concept. Approved cross-source pairs
remain exactly DIABETES/976, STROKE/494 and CASTHMA/515.

`normalize_comparison(group_a, group_b)` accepts already canonical population
strata, not natural-language text. It separates the shared fields from their
one differing dimension. Round-trip tests reconstruct both original strata
exactly, including shared unspecified/unavailable fields. If two dimensions
differ, it rejects the request instead of discarding a filter. It invents no
aliases, demographic IDs, total-population defaults or new analytical results.

`assess_query_contract(query)` performs only structural diagnostics against
the passive registry and initial intended envelopes. Unvalidated triple/race
intersections, unsupported dependencies or geography receive an unsupported
decision with the original query retained. Missing required population/time
selections receive clarification, not inferred defaults. Explicit unavailable
selections and out-of-envelope years are retained in unavailable decisions.
No alternatives are generated or automatically executed.

A ResolvedQuery can carry an unresolved/unavailable selection as a diagnostic
contract; its name does not certify observed warehouse availability. A catalog
fingerprint alone cannot enable a capability. Legacy-unverified decisions are
also non-executable; legacy execution still uses the unchanged existing pipeline.

## Representative normalized queries

These are structured intent examples, not epidemiological results. Each uses
an explicitly selected IHME cause (Stroke, cause 494), observation year 2019,
and unknown attribution. Dataset version/coverage remain unverified. Total
race and age basis in the examples below are explicit selections, not defaults
inserted by normalization.

| Research intent | Fixed filters | Comparison/grouping | Sources | Contract decision |
| --- | --- | --- | --- | --- |
| Women 40-44 versus women 60-64 | sex=Female; race=Total; fixed age unspecified because values are in ComparisonSpec | dimension=Age; A=40-44; B=60-64; county analytical universe | IHME | Planned; non-executable |
| Women versus men at age 60-64 | age=60-64; race=Total; fixed sex unspecified because values are in ComparisonSpec | dimension=Sex; A=Female; B=Male; county analytical universe | IHME | Planned; non-executable |
| Fixed female population summarized by rurality, with explicit population basis | sex=Female; race=Total; age=20+, age standardized | No pair comparison; summarize the three RUCC adjacency groups using classification year 2023 | IHME + RUCC | Planned; non-executable |
| Fixed female population summarized by rurality, population basis omitted | sex=Female; race and age remain unspecified | Same requested RUCC grouping | IHME + RUCC | Clarify explicit race and age basis; no automatic defaults |

For example, the first row can be factored without treating “Women ages
40-44” as one opaque label:

```python
from ai.query_models import (
    DemographicStratum, Dimension, PopulationValue, normalize_comparison,
)

female = PopulationValue.subgroup(Dimension.SEX, "Female")
total_race = PopulationValue.total(Dimension.RACE_ETHNICITY)
group_a = DemographicStratum(
    sex=female, age=PopulationValue.subgroup(Dimension.AGE, "40-44"),
    race_ethnicity=total_race,
)
group_b = DemographicStratum(
    sex=female, age=PopulationValue.subgroup(Dimension.AGE, "60-64"),
    race_ethnicity=total_race,
)
fixed_filters, comparison = normalize_comparison(group_a, group_b)
# fixed_filters.sex == female; comparison.dimension == Dimension.AGE
# comparison.group_a.value == "40-44"; comparison.group_b.value == "60-64"
```

No example calls a parser, queries a database or authorizes analysis.
