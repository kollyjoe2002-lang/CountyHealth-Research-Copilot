# V1.3 Phase 7 — Streamlit researcher experience

Phase 7 exposes the existing research core through human-readable selectors and
bounded conversational interaction. Researchers choose concepts; technical IDs
remain canonical execution/provenance values. No alternative analytical engine,
production deployment, AWS/IAM change, production database modification or
capability activation is included.

The approved Phase 6 commit `ae9cfca057e7d6cdb161a29a8fc7e3c685f16fa8` and its
unchanged Phase 5/4 ancestors remain intact. Phase 7 creates one normal local child
commit after applicable checks pass; its exact hash is reported on completion.

## CDC PLACES and county selection

Normal FIPS and measure-ID text inputs are removed. Measures come from
`places.measures.canonical_name`; IDs remain invisible selector values. New
catalog concepts appear without changing a page-specific disease list.

The county selector presents canonical county/equivalent names and full states,
plus available state abbreviations. Native searchable selection supports county
name, county/state and abbreviation searches. For example, the label
“Milwaukee County, Wisconsin (WI)” supports searching Milwaukee, Milwaukee
County, Milwaukee County/Wisconsin or WI. Washington County appears as separate
state-qualified choices, with no initial or arbitrary first match.

Canonical county names are preferred from the existing current-county lookup;
source geography names are retained where that lookup has no entry. The UI does
not invent County suffixes for parishes, cities or other county equivalents.
An explicit selected row is revalidated with the canonical county resolver and
must resolve to its exact FIPS. Conflicting catalog identities fail closed.

All selectors start unselected. If a dependency change invalidates a selected
value, the widget clears it rather than selecting a replacement. A valid prior
explicit choice can remain selected when still eligible.

Snapshot mode selects an observed release for the specific county/measure, with
release metadata and release-specific definitions present. It calls the original
all-measure snapshot API and restricts only the displayed measure. Source
measurement year, crude/adjusted estimates, separate confidence bounds,
carry-forward status and missing-reason fields remain visible.

Trend measurement years are observed for the selected county/measure and its
release-specific definitions. The page uses the canonical semantic measurement
period 2018–2023, an explicit subset of the existing direct API's 2017–2023
envelope. The researcher chooses years; no latest year is substituted. History
retains and labels carry-forward rows, which are not treated as independent new
measurements. Release-snapshot semantics are independent of that trend-year
policy and retain the original release/measurement distinction.

Ranking years come only from observed age-adjusted, non-null,
`carry_forward=FALSE` rows satisfying the applicable policy. No integer min/max
range is constructed. A measure without eligible years disables execution and
explains the missing eligible selection. Controller calls recheck catalogs before
calling the original analytical functions.

## Rural Health

The existing metropolitan/nonmetropolitan and detailed RUCC summaries remain,
with an additional existing-API three-group adjacency presentation. No researcher
needs to enter a numeric RUCC code. Group labels are:

- Metropolitan
- Nonmetropolitan
- Nonmetropolitan — adjacent to metro
- Nonmetropolitan — not adjacent to metro

Detailed categories use source descriptions on the chart/table rather than a
numeric-code input. Underlying classification definitions remain in provenance.
USDA RUCC **2023** is clearly described as a fixed geographic lens applied to a
health observation year, not historical rural-status change or a health outcome.

PLACES measures are selected from the same catalog. Cross-source choices are
built only by intersecting the immutable approved-pair registry with the source
catalogs. The allowed relationships remain exactly DIABETES↔976, STROKE↔494 and
CASTHMA↔515. Independently listed CHD/IHD and cancer concepts never become pairs.

Matched observation years require exact source records on the existing legacy
population basis, non-null estimates, canonical non-carry-forward PLACES rows,
a matching county, and RUCC 2023 classification. The matched-year policy is the
shared 2018–2019 interval; only observed eligible years within it are selectable.
This existence check does not certify complete or representative coverage. An
approved pair without an eligible year leaves execution disabled.

PLACES modeled prevalence/confidence intervals and IHME YLL burden/uncertainty
intervals retain separate semantics. Cross-source plots remain separate panels
and separate table columns. IHME attribution and unit scale are not upgraded.
County means and medians are explicitly county-weighted, not population-weighted
national estimates. These remain descriptive, noncausal summaries.

## Conversational Research Report

The page calls `submit_research_turn`, a thin adapter to `run_research_turn`.
There is no UI parser, resolver, planner, SQL, executor or alternative execution
path. No development path/marker/activation argument is exposed.

Researchers use a chat input and see their latest message with the current
assistant response. Source clarification → “Both”, missing year → “2019”, and
other supported follow-ups use the original bounded intent state and full
canonical revalidation. Alternatives are text proposals, not automatically
executed buttons. “Start a new research question” explicitly resets intent and
results rather than changing a pending question silently.

Visible outcome labels distinguish clarification, PLANNED/not activated,
unsupported analysis, data/year unavailability, infrastructure failure, capability
guidance, validated answers, and evidence without a validated narrative. Normal
responses use Phase 6 explanations rather than raw resolver or database errors.
Infrastructure failure is not represented as scientific data absence.

Capability summaries use the canonical deterministic summary layer. Wording
aliases add “What years do you have?” and “Do you have breast cancer data?”.
Without checked catalogs, disease coverage remains explicitly catalog-dependent.
A catalog-refresh outage preserves the previous snapshot only for intent
continuity, with a visible warning that current availability is not established.

Legacy beta traffic classification, anonymous session identity, internal-test
authentication, feedback backend and telemetry privacy behavior remain. Internal
traffic is still excluded from genuine researcher feedback/traffic.

## Preview, provenance and source-language guard

The interpreted-query table projects canonical plan/context or normalized
multidimensional preview fields into strings, never Python objects. It includes
applicable concept/source, scope, fixed sex/age/race, comparison dimension/groups,
rurality filter/lens, observation years and policy assumptions/defaults.

Requested values, normalized intent awaiting catalog resolution, resolved values
and policy bases are labelled separately. A public PLANNED draft does not claim
that its cause, county or strata have passed warehouse resolution. Legacy IHME
fixed population bases derive from registry metadata and dimension rules.

For a resolved multidimensional query, presentation verifies the exact canonical
preview and runs plan identity checks before displaying results where steps
exist. It never constructs a replacement query. Permanent tests detect preview
identity tampering.

Optional provenance includes county FIPS, measure/cause IDs, release and
measurement years, registry/capability metadata and RUCC classification year.
Rural summaries include eligible source-release years separately from observation
years. IDs are outputs, not prerequisites for ordinary use.

Inspection found pre-existing legacy report templates that assert
“high-BMI-attributable” YLL. Those APIs remain unchanged. The UI supplements
canonical grounding with the existing fail-closed source-language guard: it
withholds unsafe narrative/report exports rather than publishing unsupported
attribution/unit claims or rewriting evidence. Canonical evidence remains
available with an explanation. Safe reports/interpretations retain the existing
report/export structures. This presentation gate is not a replacement for
entailment or a claim that legacy provenance has been verified.

## Session-state discipline

Streamlit retains only the Phase 6 bounded current intent, a current catalog
snapshot, the latest exchange, current result presentation and existing
beta/feedback presentation metadata. There is no transcript list, new persistence
backend or fixture execution permission in state.

The existing state-invalidation rule is shared by the core and presentation
reruns. Registry/catalog change, expiration or turn exhaustion clears stale
intent and displayed results and requests restatement. Every new submission
clears prior analytical presentation before invoking the canonical turn API.
Phase 6 limits remain eight turns, thirty minutes and its existing text/byte
bounds. The latest exchange can survive ordinary Streamlit reruns without
independently merging intent in the page.
