The schema `ihme.burden` contains sex, age, race, cause, measure, metric,
year, FIPS, values and bounds. Schema presence does not prove availability
of each sex × age combination. The analytical DuckDB file is excluded from

against dataset/import provenance before enabling new evidence claims:
measure_id=4 and metric_id=3 alone do not encode high-BMI attribution.

## Proposed contracts and ownership

Introduce `ai/capabilities.py` as the versioned canonical static registry.
Each immutable capability specifies source/domain, operation key, allowed
comparison dimension, allowed fixed dimensions, defaults, geography modes,
measure/adjustment restrictions, pair compatibility, validation status, and
validator references. Separate planned capabilities from executable ones.
Only capabilities with passing validators can be advertised as executable.
Existing functions remain explicitly bound in the executor's allowlist;
a consistency validator requires the registry and callable map to agree.

Introduce `ai/query_models.py` for structured contracts, re-exported where
needed to avoid breaking existing imports:

- `DemographicStratum`: sex, age, race/ethnicity, each independently resolved.
- `ComparisonSpec`: one comparison dimension and two distinct group values.
- `GeographySpec`: eligible county universe, optional county/state scope,
  optional RUCC filter/grouping, classification year and missingness policy.
- `TimeSpec`: source-specific measurement years/ranges, release selection,
  and explicit contemporaneous or contextual alignment mode.
- `ResolvedQuery`: canonical source concepts, filters, comparison, geography,
  time, assumptions, capability/version and data-availability fingerprint.
- `CapabilityDecision`: supported, reason code, missing constraints and
  structured nearest alternatives. No analytical values.

Unspecified, total-population, and unavailable are distinct values. Reject
conflicting fixed and comparison constraints. Never discard a fixed filter
to fit a supported query. Normalize omitted legacy defaults explicitly.

Example: “Compare ischemic heart disease among women ages 40–44 and 60–64”
becomes IHME YLL rate attributed to high BMI; sex=Female, race=Total;
comparison=age, A=40–44, B=60–64; eligible counties; explicit/defaulted
validated IHME year. Age-specific rates must not be called age-standardized.
Resolve each age label against the catalog; do not invent ID values.

Introduce `ai/evidence_semantics.py` with immutable per-source
`EvidenceSemantics`: source, dataset/version, measure, metric, concept,
attribution, population basis, unit, adjustment, uncertainty type/level,
measurement year, release year, classification year where relevant, and
source provenance. Unknown provenance is explicit and blocks claims that
require it. PLACES confidence intervals and IHME uncertainty intervals
remain distinct. RUCC is a classification, not a health outcome.

Cross-source evidence is a bundle of separate source items plus alignment
metadata; never one shared metric/population label. PLACES contextual
prevalence is not evidence about the selected IHME sex/age subgroup.

## Initial validation envelope

| Combination | Initial supported shape after validation | Restrictions |
| --- | --- | --- |
| Sex × age | Compare two age groups with fixed sex, or two sexes with fixed age | Race=Total; no age-standardized category mixed with age-specific categories. |
| Sex × rurality | Compare sexes within RUCC strata, or summarize a fixed sex across RUCC groups | Race=Total; validated default age basis; no additional age-specific filter. |
| Age × rurality | Compare ages within RUCC strata, or summarize a fixed age across RUCC groups | Race=Total; Both sexes; no fixed sex subgroup. |
| Legacy race comparison | Existing validated behavior | No new race intersections. |

One comparison dimension per request. No unrestricted factorial tables,
sex × age × rurality, race intersections, interactions, or significance
claims. Other combinations fail closed with a precise explanation.
PLACES has no newly inferred demographic strata. Validate each source,
operation, fixed-filter shape and grouping orientation separately.

## Deterministic analytics and coverage

Add `app/multidimensional.py` for reusable read-only primitives:
`get_stratum_values`, `compare_strata`, `summarize_by_rurality`, and
`align_source_context`. Names are proposed interfaces, not existing APIs.
Retain old data-access functions unchanged until parity is demonstrated;
then delegate only where outputs, defaults and ordering are identical.
Use registry-owned SQL column identifiers and bound values exclusively.
No schema writes or precomputed tables are required by this design.

Build the eligible county universe from the existing current-county
eligibility rules before filtering observations. Read only requested
cause/year/strata; avoid full warehouse scans and Cartesian expansions.
Verify unique analytical keys before pivoting or joining. Existing MAX
pivot behavior must not mask duplicates in new functions. Reject duplicate
keys rather than choose a row or average them silently.

For demographic comparisons, A and B are paired within each county.
Report A minus B, gap magnitude, and existing relative-gap definition;
zero denominator yields unavailable relative gap. Do not derive a gap
uncertainty interval from marginal bounds without a validated method.
Rurality groups contain different counties: summarize within groups and
label county-weighted mean/median correctly; do not call this a paired
county comparison or a population-weighted national rate.

`CoverageDiagnostics` records eligible counties, A availability, B
availability, complete paired counties, exclusions with mutually exclusive
primary reasons, and additional overlapping diagnostic flags. Paired
coverage = 100 × complete/eligible; zero denominator returns unavailable.
For rurality summaries provide these counts within every eligible RUCC
stratum and report missing RUCC separately. For geographic group contrasts
record both disjoint denominators; paired counts are not applicable.

Distinguish absent rows, null estimates, unavailable combinations, missing
geography and source-declared suppression. Never infer suppression from
absence. Preserve valid zero estimates. For cross-source joins record IHME
availability, PLACES availability, their intersection and unmatched
counties before dropping rows. Provide per-year coverage for trends.

Preserve canonical PLACES carry_forward=FALSE and validated release
selection. Reject ambiguous duplicate measurement-year rows pending an
explicit validated selection rule. Query years from data for the selected
measure, adjustment, county scope and canonical policy, not broad min/max
bounds alone. Explicit unavailable years are never silently replaced.
Concurrent evidence uses the actual source-year intersection. Different
source years require explicit contextual alignment and a visible time gap.
RUCC 2023 applied to earlier observations is a fixed geographic lens,
not a historical rurality trajectory. Do not extend cross-source mappings.

## Semantic and conversation flow

Parser -> typed request -> capability shape check -> canonical resolution
-> observed availability check -> validated plan -> executor recheck
-> deterministic evidence -> claims -> existing grounded interpretation
and entailment validation -> report/export.

Extend the parser's strict schema, adapter and planner together. Include
fixed filters, comparison dimension, source years and geography in the
interpreted-query preview, derived from the resolved execution query.
Unresolved previews must show uncertainty rather than resolved-looking IDs.
Changing the preview rebuilds and revalidates the plan.

Reason codes include DATA_UNAVAILABLE, YEAR_UNAVAILABLE,
DEMOGRAPHIC_COMBINATION_UNSUPPORTED, OPERATION_UNSUPPORTED, and ambiguity
or infrastructure failure separately. Database errors must not be presented
as scientific lack of data. Fallback text acknowledges the intended query,
states the exact missing capability, and offers only registry-supported,
availability-checked alternatives. Alternatives require user selection;
never execute a weaker question automatically.

A bounded session conversation retains the current resolved query and
clarification state. Follow-ups merge explicit edits into that state,
then run the full validation pipeline again. Ambiguous referents prompt
clarification. Invalidate stale results when query, registry or catalog
changes. Fallback produces no epidemiologic numbers. Preserve telemetry
scope and existing privacy/security behavior; no new persistence backend.

## Researcher controls and catalog

Add dataset-driven catalog accessors in `app/data_access.py` for PLACES
counties, measures, releases and canonical years, plus scoped IHME strata
availability. Cache against dataset/version identity and clear on refresh.
Do not use the IHME-only eligible county selector as the entire PLACES
county universe. Reuse `resolve_county` ambiguity behavior and state labels.

CDC PLACES: searchable county/state names, canonical health measure labels,
separate release-snapshot and measurement-year modes, scoped year options.
Rural Health: readable measure labels, approved concept-pair selector,
explicit separate source years, readable RUCC labels and classification year.
Technical IDs appear in advanced provenance only. Disable unavailable
options and explain why; UI choices never substitute for executor validation.
Research Report: bounded multi-turn history, preview, coverage, evidence
semantics and conversational fallback, using `run_research_assistant` only.

## Implementation sequence and acceptance gates

1. Phase 2: add passive registry and evidence contracts; inventory all
   existing executable operations and mappings; add consistency/semantics
   validators. No consumer behavior change until legacy parity passes.
2. Phase 3: typed demographic, geography and time contracts; resolver
   catalogs; table-driven fixed/comparison conflict tests and unavailable
   combination checks. Keep new capability entries disabled.
3. Phase 4: deterministic sex × age first, then sex × rurality and age ×
   rurality. Add tiny isolated DuckDB fixtures for duplicate/null/zero/
   missing-RUCC/partial-pair cases; validate real warehouse coverage on a
   separate development copy before marking capabilities executable.
4. Phase 5: strict parser schema, adapter, planner, resolver, request policy
   and executor integration. Test every supported orientation and negative
   intersection; preserve forecast and concept-pair rejection.
5. Phase 6: structured reasons, grounded alternatives and bounded follow-up
   state. Validate that unsupported queries never execute or fabricate data.
6. Phase 7: Streamlit catalog controls, query preview and conversation.
   Test state invalidation, ambiguous counties and unavailable years.
7. Phase 8: full legacy and new gates, generated capability documentation,
   scientific-semantics review, performance checks, release-readiness report.
   Stop before deployment for user review.

At each checkpoint run targeted validators and git diff --check; commit
small coherent changes only when their applicable checks pass. A blocked
warehouse/live gate is recorded as blocked, never green. Any scientific
meaning change beyond this specification requires explanation before work.

New permanent validators: capability consistency, evidence semantics,
sex-age, sex-rurality, age-rurality, coverage diagnostics, conversational
fallback/follow-ups, human-readable resolver/UI behavior and preview-plan
identity. Add negative tests for triple intersections, unsupported race
filters, duplicates, carry-forward rows, population mismatch, unmatched
source years and breast-cancer/PLACES-CANCER mapping.

Keep all legacy suites listed in the handoff: full-chain, PLACES semantic,
PLACES-IHME semantic, rurality semantic, disparity semantic, concept
compatibility, evidence language, request policy, stress matrix, lay
language, live parser, semantic entailment and deterministic cross-source
suite. Current execution evidence is recorded separately in
`V1.3_Baseline_Assessment.md`; historical release pass counts are not a
substitute for a fresh run.
